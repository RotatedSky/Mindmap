# Mindmap 开发路线图 / Roadmap

本文档记录工具的现状、已知限制与后续开发计划。功能开发遵循 `docs/development-workflow.md` 工作流，每项完成需通过 npm test / fuzz / 冒烟并按提交模板收尾。

## 现状快照

- 技术栈：纯前端零依赖（IIFE 模块挂载 `window.MM`），13 个模块约 5100 行，PWA 离线可用
- 质量基线：Node 内置测试 154 项、fuzz 随机测试、Playwright 浏览器冒烟（`tools/smoke_ui.py`）
- 交互：节点增删改 / 拖拽 / 3 种布局方向 + 自由布局 / 展开收起 / 撤销重做（100 步）/ 剪贴板子树 / 全局搜索 / 大纲双向联动
- 图形增强：节点样式面板（背景 / 文字 / 边框 / 圆角 / 字号 / 加粗）、外框（嵌套 / 避让 / 样式 / 标签）、关联线（注释 / 拖拽 / 方向）、着色、图片 / 链接 / 备注
- 内容：Markdown 导入导出、LaTeX 公式（KaTeX 0.18 本地离线）
- 视觉：6 套主题、画布背景色、连线层级配色（默认单色 / 彩虹 / 冷色 / 暖色 / 莫兰迪 / 黑白灰）
- 导出：PNG / JPEG / SVG / PDF（含外框与关联），Chromium 支持 File System Access 选择保存路径
- 持久化：localStorage 自动保存（400ms 防抖）+ JSON 导入导出

## 已知限制

| 编号 | 限制 | 位置 |
|---|---|---|
| L1 | localStorage 约 5MB 限额，大图会 QuotaExceededError | `js/storage.js` |
| L2 | 图片 ≤2MB，base64 内嵌，体积大 | `js/editor.js` 添加图片 |
| L3 | 远程 URL 图片无法保证进入导出文件 | README / 导出 |
| L4 | 直接双击 `index.html` 打开时 PWA 不生效 | sw.js |
| L5 | 保存路径选择依赖 Chromium（showSaveFilePicker），其余浏览器回退下载 | `js/exporter.js` |
| L6 | `editor.js` 1386 行过大（指针 / 键盘 / 拖拽 / 右键 / 面板） | `js/editor.js` |
| L7 | 无多文档 / 多标签管理，无本地文件回写 | storage / app |
| L8 | 手机触控为基础支持（长按 = 右键） | `js/editor.js` |
| L9 | 无千节点压测基准，大图布局 / 渲染性能未量化 | layout / render |

## 路线图

优先级：P0 短期（体验巩固）→ P1 中期（能力扩展）→ P2 长期（生态）。

### P0 短期 · 体验巩固（纯前端零依赖）

| 项 | 目标 | 验收标准 | 关联限制 |
|---|---|---|---|
| 1. 存储升级 | IndexedDB 替换 localStorage，旧数据无缝迁移 | 保存 >10MB 数据不报错；首次加载自动迁移旧 localStorage 数据；格式仍向后兼容 | L1 |
| 2. 图片增强 | 拖拽 / 粘贴直插图；上限可放宽并压缩 | 图片可拖入节点；超大图自动降质压缩不崩 | L2 |
| 3. 本地文件 | `.mind` JSON 关联打开 / 另存回写 | Chromium 下可打开已有文件并回写，未改动覆盖前有防止意外提示；非 Chromium 走 JSON 导入导出 | L7 |
| 4. 导出增强 | 仅导出选中分支 / 外框；文件名带标题；Markdown 导出补图片与备注 | 分支导出与整图结果一致且含外框；Markdown 含图片引用 | L3 |
| 5. 性能 | 千节点压力基准 + 文本测量缓存 + 增量布局 / 渲染 | `tools/bench.js` 建立基线；千节点交互无明显卡顿；总量化指标记录于文档 | L9 |
| 6. UI 打磨 | 空态引导、右键菜单分组、深色跟随系统、快捷键表补全 | 首次无数据时展示引导；系统深色时默认主题可选跟随 | — |
| 7. 测试补强 | outline / notes / render 覆盖率提升；跨浏览器冒烟 | 新增用例全部通过；Firefox / WebKit 冒烟可跑 | — |
| 8. 小地图 | 画布右下角小地图，实时预览全图，点击 / 拖拽跳转视野 | 大图下可快速定位跳转；小地图缩略图随主题 / 背景生效；缩放平移时实时同步 | — |
| 9. 外框布局优化 | 外框布局更紧凑自然：嵌套间隔可按内容自适应、边缘避让边界条件补全 | 嵌套框间距在无标签时更贴合成员；极端嵌套 / 收起组合下外框不相交、不压节点；现有外框测试不降级 | — |

## 重构主线（贯穿 P0，伴随式推进）

代码重构是路线图的一部分，但采用"伴随式"策略：每次触碰某块代码时顺带清理，避免独立大重构阻塞功能交付。安全网已具备（154 项测试 + fuzz + 冒烟 + `window.MM` 接口约定），重构后须保持接口兼容并全量回归。

| 项 | 目标 | 验收标准 |
|---|---|---|
| R1. 拆分 `editor.js` | 指针事件、键盘、拖拽、右键菜单、样式面板逻辑独立成模块 | 拆分后 `window.MM` 对外接口不变；npm test / fuzz / 冒烟全绿；文件行数回落并记录于 README |
| R2. 数据格式版本化 | JSON / localStorage 格式加版本号 + 迁移框架 | 旧格式数据（含无 style 字段的外框等）可自动迁移加载，不破坏向后兼容 |
| R3. 渲染与布局解耦 | render / layout 关键函数纯化，便于单测与性能优化 | 已有 render / layout 测试不降级，新增性能基准可度量 |

## 推进顺序

建议按 P0 的 1 → 3 → 4 → 5 顺序推进，重构任务穿插其中（如做存储升级时顺带拆分 `storage` 相关逻辑）；小地图（8）与外框布局优化（9）可视需求提前穿插；每项走完整工作流（方案设计 → 开发 → 测试 → 冒烟 → review → 提交）。
